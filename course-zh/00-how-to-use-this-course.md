# 第 00 章 — 如何使用本课程

## TL;DR

你即将学习生产级 agentic 系统的设计方式 —— 不是通过阅读别人成千上万行的代码,而是沿着一张模式地图走一遍,并与你自己的 AI agent 结对,把这些模式应用到你真正想做的项目上。本章解释了为什么本课程要这样写、如何带着 agent 在身边阅读它,以及如何把每一章个性化为你可以交付的东西。一切都围绕你和你的项目。

---

## 这门课为什么存在

2026 年初,我一遍又一遍看到同样的事情发生。一个从没写过一行代码的人,打开 Claude 或 Codex,描述一个问题,四十分钟后就对着一个能逐行看懂的、跑得起来的原型出神。一位过去要花一周啃新框架的资深工程师,如今粗读一遍文档、向自己的 agent 抛出五个一针见血的问题,当天下午就能上线。起点各异,那个循环却始终如一:一个好奇的人、一个诚实的问题,加上一个 AI 伙伴——它就在对话里解释概念、搭好骨架、当场把代码跑起来。

这种学习方式,大约比看视频或跟着分步教程**快十倍**。视频是被动的,而且被定格在它录制的那一刻。教程则过度贴合某一个技术栈,新模型一发布就开始过时腐坏。AI agent 恰好相反——它互动、最新,还为你量身定制。瓶颈不再是信息本身,而是知道该问什么。

这门课就是为此而生。它正是 agent 自己递不到你手上的那张地图。厂商也不会给你这张地图,因为每一家都希望你认定:他们的框架**就是**地图。可当你读完业内讨论最多的那几个生产级 agent —— OpenCode、Hermes Agent、OpenClaw、Paperclip 等 —— 的源码,有件事会变得一目了然:它们翻来覆去就是同样的十几个想法。名字不同、文件结构不同,底层却是同一套模式。这门课要做的,就是把这些模式一次性讲清楚——用大白话,连同那些真正重要的取舍一起写下来。

## 这门课是什么,不是什么

这门课是一根**主干** —— 出现在每一个严肃的 agentic 系统里的承重话题、模式与决策。它包含图示、术语、失败模式、设计选择,以及来自真实生产系统的笔记。它对 *该思考什么* 持有明确观点,对 *该 import 哪个库* 几乎不发一言。

这门课**不是**分步教程。没有"先装这个、再粘那个"。没有一个我们从头到尾一起走的项目。没有小测验、没有要克隆的 capstone 仓库、没有只能在某个技术栈上跑的 notebook。

这是有意为之。一门课里过时最快的那些细节 —— SDK 版本、模型名称、框架 API、价格 —— 恰恰是你的 agent 手里答案最新的部分。而过时最慢的那些 —— 工具注册表到底是什么、做规划时何时该用清单、何时该用图、记忆是怎么被"投毒"的、缓存为什么会失效、什么时候该把人拉进回路 —— 才是你在这里要学的东西。

可以这样理解:我给你的是一副骨架,你的 agent 帮你把肌肉一块块长上去。

## 如何真正使用本课程

无论你有十年工程经验,还是从没碰过终端,这门课用起来都一样。区别只在于你给 agent 喂什么样的 prompt。挑那些贴合你当前水平的——当然,不管你什么背景,每一章都用最简单的那几句也完全没问题。*"当我是个 13 岁小孩,讲给我听"* 这一招永远不过时。

**理解一章**(适用于任何读者,无论是否有技术背景):

- *"用我完全不懂任何行话的方式向我解释这一章。每个术语第一次出现时给出定义。"*
- *"举三个真实世界中这件事很重要的例子。"*
- *"我从这一章里应该记住的一件事是什么?"*
- *"我没问出来、但本该问的一个问题是什么?"*

**把它应用到你的项目**(当你心里已经有想做的东西):

- *"我刚读了 [模式 X]。我在做 [你的项目]。把这个模式翻译成在合适的语言和工具里最小但真正能跑的版本,边写边解释每个部分。"*
- *"这是 [第 NN 章] 警告过的失败模式。看一下我们之前做的东西,告诉我哪些已经成了风险。"*
- *"给我两种做法以及各自的取舍,三个 bullet 概括 —— 不要写成段落。"*

**与真实系统对照**(当你想给一个想法找个落脚点):

- *"先把我的项目放一边 —— 给我看看 OpenCode(或 Hermes、Codex、Claude Code)是如何处理这件事的,以及我们应该借鉴什么。"*

**自测**:

- *"就这一章考考我。问我五个问题,从简单到难。"*

如果你没有技术背景,上面靠前的那几个 prompt 会是你用得最多的。代码交给 agent 写;你的活儿是读它产出的东西、判断它讲不讲得通、然后问出下一个问题。书上那些术语,会比你以为的更快地不再像天书。

## 这门课如何变成你自己的项目

个性化不是课程末尾的独立步骤。它发生在每一章里、发生在你和你 agent 的对话中。

到第 02 章,你手里会有一个调用单个工具的小循环。到第 05 章,它能在多轮对话之间记住东西。到第 10 章,它能把任务委派给更小的专家 agent。到第 16 章,你能看清它花了多少钱、时间都耗在了哪里。到第 22 章 —— 最后一章 —— 你坐下来,和 agent 一起过一遍设计画布,定下你真正的系统需要什么、又不需要什么。

你也可以反过来走。如果你已经知道你的项目 —— 一个研究助手、一个内部编码 agent、一个客服工作流、一个个人事务助理 —— 先挑出与之匹配的章节,把其余的当作背景阅读。第 22 章会帮你选。

目标不是读完这门课。目标是交付一个你本来就想做的东西,并且能看懂里面的每一行。


## 课程剩下部分的形态

还有二十一章。它们从最小的机制一路搭到最大的关切。

- **Ch.01–02** — agent 循环本身:一次工具调用,然后是多次。
- **Ch.03–04** — 工具与 prompt:与模型之间的契约。
- **Ch.05–07** — 记忆:短期、长期,以及如何安全地写入。
- **Ch.08** — 状态与持久化:从崩溃中活下来。
- **Ch.09–10** — 规划与多 agent 委派。
- **Ch.11** — 把这一切组装成一个 harness。
- **Ch.12–14** — 人、连接器、技能 / MCP / 子 agent:agent 向外界呈现的表面。
- **Ch.15–17** — 后端、可观测性、成本:生产层。
- **Ch.18–19** — 安全与运维。
- **Ch.20–22** — 主动型 agent、自演进 agent,以及最后,设计你自己的 agent。

章节顺序经过编排,后一章只依赖前面已经讲过的内容。如果你的项目方向明确,可以跳过暂时用不上的章节,等用得上时再回来。

## 全书引用的参考系统

当某一章里出现 "真实系统笔记"(real system note)时,指的是下面这几个:

- **OpenCode** —— 一个编码 agent harness,带有类型化工具、权限、会话、压缩(compaction)和终端 UI。
- **Hermes Agent** —— 一个个人助理,具备内存、技能、cron、消息集成,以及后台的 review 循环。
- **OpenClaw** —— 一个自托管的助手网关,最大特长在于通过 channel adapter 把众多平台收敛到一个助手边界之内。
- **Paperclip** —— 一个工作流控制平面:agent、issue、预算、审批、密钥、持久化的 Postgres 状态、审计日志。

它们不是供你照抄的模板,而是一组现实对照。如果本课程里的某个模式,在它们之中至少两个的生产环境里都出现过,那它就是承重的。如果只有一个用,书里会把其中的取舍讲清楚。

## 开始前的最后一件事

你不需要任何许可才能开始。你不需要在打开 agent 之前读完每一章。你不需要先知道自己最后会用哪个框架。你做的第一个东西会小到那些决定都还无所谓 —— 一旦它摆在你面前并且能跑,下一个决定就会变得显而易见。

今天做出最有意思的 agentic 系统的那批人,并不是经验最多的人,而是最早跟 AI 伙伴形成紧密协作循环、并且在这个循环里待得最久的人。这门课存在的意义就是:当你身处那个循环之中,你知道该问什么。
